# Учёба с Лучиком · бот и мини-приложение MAX

<img src="docs/assets/luchik-avatar.png" alt="Лучик — персонаж проекта" width="160">

Прототип для хакатона для учеников 1–7 классов: регистрация по имени MAX, случайный класс в этом диапазоне, тестовый электронный дневник, пять блоков теории и проверка ответов через RouterAI `inclusionai/ling-3.0-flash-vl`.

## Ссылки для проверки и назначение

- Бот MAX: [@t696_hakaton_max_bot](https://max.ru/t696_hakaton_max_bot). Мини-приложение открывается из бота; публичный HTTPS-адрес приложения и API: <https://85-159-231-99.sslip.io/>.
- Исходный код: <https://github.com/daredevilg7/maxHackathon>. Ссылка на опубликованный commit и адреса сервиса указаны на первом техническом слайде презентации.
- Основная аудитория MVP — ученик 1–7 класса, которому нужна короткая подготовка по конкретной теме. Он открывает бота в MAX, переходит в мини-приложение, выбирает предмет и тему, проходит пять объяснений и вопросов, получает обратную связь и видит прогресс.
- Проблему подготовки команда изучила в пилотном опросе 49 учеников 7–9 классов одной школы; результаты и границы исследования приведены ниже. Улучшение учебных результатов от использования «Лучика» пока не измерено.

Бот служит входом, показывает профиль, расписание и предлагает выбор темы. Мини-приложение и собственный FastAPI обслуживают основной учебный сценарий. SQLite сохраняет аккаунт, синтетическое расписание и прогресс; RouterAI генерирует и проверяет материалы. Настоящая интеграция с электронным дневником отсутствует. API здесь нужен мини-приложению и боту; по условиям хакатона само наличие API дополнительных баллов не даёт.

## Исследование проблемы и границы выводов

В презентации команды приведён **пилотный опрос 49 учеников 7–9 классов одной школы** о трудностях подготовки к самостоятельным работам. Из них 55% сообщили, что не знают, что именно повторять; 20% долго ищут понятное объяснение; 16% испытывают сложности с подбором заданий; 8% не отметили заметных трудностей. Проценты в презентации округлены, поэтому их сумма составляет 99%. Опрос поддерживает вывод о существовании проблемы **у опрошенной группы**, но не доказывает её распространённость среди всех школьников и в особенности нынешней аудитории MVP — 1–7 классов. Метод отбора и формулировки вопросов в презентации не раскрыты; это ограничивает обобщение результатов.

Сам продукт уже работает, но **эффект от него остаётся гипотезой для пилота**. Ещё не измерены время до первого задания, доля завершивших пять шагов, понимание темы после подсказки и ясность следующего шага. В текущем MVP ученик сам выбирает предмет и тему; отдельной начальной диагностики пробелов, прогноза готовности к самостоятельной работе и напоминаний бот пока не делает. Эти возможности в презентации помечены как дальнейшее развитие, а не как функции работающей версии.

Серверная часть бота и мини-приложения **уже запущена и работает на VPS** `85.159.231.99`. Nginx принимает HTTPS и передаёт запросы приложению в Docker. Используйте следующие адреса:

|---|---|
| Ссылка на бота MAX | `https://max.ru/t696_hakaton_max_bot` |
| **URL мини-приложения в настройках бота MAX** | **`https://85-159-231-99.sslip.io/`** |

| Внешний API модели RouterAI | `https://routerai.ru/api/v1` |

В настройках мини-приложения MAX укажите именно URL с `/` в конце из второй строки таблицы. Адрес webhook предназначен для событий бота и уже зарегистрирован на сервере; его не ставят вместо URL мини-приложения. Мини-приложение обращается к собственному API на том же домене по путям `/api/...`, поэтому отдельный адрес API в браузерном коде не нужен. Токен бота MAX используется сервером для запросов к `https://platform-api2.max.ru`.

Для работающего VPS в `/opt/maxbot/.env` должны быть `DOMAIN=85-159-231-99.sslip.io`, `PUBLIC_BASE_URL=https://85-159-231-99.sslip.io`, `PORT=8001`, `BOT_MODE=webhook`, `DEMO_MODE=false`, `MAX_BOT_USERNAME=t696_hakaton_max_bot`, `MAX_BOT_TOKEN` от организаторов и `WEBHOOK_SECRET` для MAX. Внешний AI настраивается отдельно: `ROUTERAI_BASE_URL=https://routerai.ru/api/v1`, `ROUTERAI_MODEL=inclusionai/ling-3.0-flash-vl`, `ROUTERAI_API_KEY` — действующий AI API токен команды. На сервере AI ключ уже настроен; пользователь сам внесёт нужный токен на технический слайд презентации и сверит его с серверным значением перед сдачей. Значение токена не помещают в Git, OpenAPI и клиентский JavaScript. Совпадение серверного ключа с будущим значением на слайде отдельно не подтверждалось.

Для смены AI токена откройте `/opt/maxbot/.env` на сервере, замените только `ROUTERAI_API_KEY`, затем выполните в `/opt/maxbot` `docker compose up -d --force-recreate app` и проверьте `/health` и создание урока в MAX. Это не требует изменения URL, Nginx или webhook-подписки. Не отправляйте токен в чат или командную строку, которая сохранится в истории оболочки. 29 сентября 2026 года короткий запрос к RouterAI с текущим серверным ключом успешно проверил тему «Сложение» для 1 класса.

## Самый быстрый запуск — Docker

1. Установите и запустите Docker Desktop (на сервере — Docker Engine и Compose).
2. В чистом checkout выполните `cp .env.example .env` и оставьте демонстрационные значения `DEMO_MODE=true`, `BOT_MODE=disabled`. Заполненный `.env` никогда не коммитьте. Откройте терминал в папке проекта:

```sh
docker compose up -d --build
```

3. Откройте http://localhost:8000.

В деморежиме можно зарегистрировать демонстрационного Сашу и пройти готовый урок про дроби. Этот режим **не вызывает AI**, ничего не отправляет в MAX и не требует оплаты. Проверка демонстрационных ответов — простое сравнение с эталоном; ответы своими словами проверяются настоящим AI после подключения RouterAI. Демоаккаунт общий для локального просмотра.

Стартовый экран устроен как комната Лучика: персонаж меняет выражение после двух верных ответов, пять звёздочек показывают прогресс дня. Урок открывается короткими сценами «Идея → Пример → Твой ход». Уроки «Обыкновенные дроби» и «Сокращение дробей» состоят из проверенных коротких шагов; для других тем шаги составляет AI. Если объяснение оказалось сложным, кнопка «Не понял? Объясни проще» переписывает текущую теорию и пример, сохраняя вопрос и прогресс. После неверного или не относящегося к вопросу ответа Лучик даёт подсказку, а следующий шаг открывается только после верного ответа. После обновления страницы — «Продолжить урок». Текущее занятие можно отменить и сразу выбрать другую тему; уже полученные верные ответы остаются в прогрессе дня.

Раздел «Мои темы» хранит завершённые занятия. Для каждой темы можно пройти новый тест из пяти вопросов: четыре с выбором ответа и одно задание на соответствие. В обычном режиме вопросы составляет AI по материалам пройденного урока; ответы и лучший результат сохраняются. На главном экране показана серия дней, в которые ученик отвечал на вопросы урока или теста. Серия сохраняется между запусками приложения и допускает ещё не начавшийся текущий день.

Перед созданием урока по теме ученика RouterAI проверяет, относится ли она к выбранному школьному предмету. Эта проверка действует и при выборе темы в чате бота, и при запуске урока в мини-приложении. Неподходящая тема или недоступность AI останавливает создание урока; ученик может указать другую тему.

## Где настраивать токены

Редактируйте **`.env`** в корне проекта. Он скрытый: в Finder нажмите `Cmd + Shift + .`, чтобы показать скрытые файлы. `.env.example` — шаблон без ключей. Не отправляйте заполненный `.env` в репозиторий или участникам вне команды. В Docker-образ ключи не копируются.

```dotenv
MAX_BOT_TOKEN=токен_от_организаторов
MAX_BOT_USERNAME=имя_бота_без_собачки
ROUTERAI_API_KEY=AI_API_токен_из_технического_слайда_презентации
ROUTERAI_MODEL=inclusionai/ling-3.0-flash-vl
DEMO_MODE=false
BOT_MODE=webhook
DOMAIN=study.example.ru
PUBLIC_BASE_URL=https://study.example.ru
WEBHOOK_SECRET=случайная_строка_от_24_символов
```

Создать секрет webhook:

```sh
docker compose run --rm app python -m app.cli secret
```

Скопируйте результат в `WEBHOOK_SECRET`. После изменения `.env` применяйте `docker compose up -d --force-recreate` (на сервере — с обоими Compose-файлами, как ниже).

## Подключение к MAX на сервере

Ниже описан вариант для **нового сервера**, где порты 80/443 свободны: используется `compose.production.yaml` с Caddy. Текущий VPS уже использует Nginx для нескольких сайтов; его фактическая конфигурация описана в разделе «Текущий VPS». На нём `compose.production.yaml` запускать нельзя без перенастройки занятых портов.

1. Скопируйте проект на сервер. Направьте DNS A-запись домена на IP сервера. Откройте входящие TCP 80 и 443; если есть AAAA-запись, IPv6 тоже должен вести на этот сервер. Порты не должны быть заняты другим веб-сервером.
2. Заполните `.env` по примеру выше. `DOMAIN` — только домен, `PUBLIC_BASE_URL` — с `https://`.
3. Настройте доверенный сертификат для исходящих запросов к MAX, если он ещё не доступен системе — см. следующий раздел.
4. Запустите приложение и Caddy. Caddy получает и обновляет публичный TLS-сертификат автоматически:

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

5. Проверьте токен (команда печатает имя бота, без токена):

```sh
docker compose -f compose.yaml -f compose.production.yaml exec app python -m app.cli check
```

Запишите показанный `username` в `MAX_BOT_USERNAME`, если ещё не указали его, затем выполните `up -d --force-recreate` с обоими файлами.

6. Когда `https://ваш-домен/health` возвращает `{"status":"ok"}`, подключите события:

```sh
docker compose -f compose.yaml -f compose.production.yaml exec app python -m app.cli webhook
```

7. В настройках **этого же бота** на платформе MAX укажите URL мини-приложения `https://ваш-домен/` и включите кнопку открытия. Если на хакатоне выдали только токен, попросите организатора добавить этот URL к боту: одного токена может быть недостаточно для доступа к настройкам мини-приложения.
8. Откройте бота, отправьте `/start`, нажмите «Открыть Лучика», затем «Создать учебный аккаунт». Имя и ID поступят из проверенных данных MAX; вручную представиться чужим пользователем нельзя.

Production Compose принудительно отключает деморежим. Приложение не стартует в режиме webhook без токена или достаточно длинного секрета. Пустой/неверный ключ RouterAI выводит понятную ошибку в уроке, не подменяет ответ демонстрацией.

## Текущий VPS и обнаруженная конфигурация

На 29 сентября 2026 года проект развёрнут в `/opt/maxbot` на предоставленном VPS. Запущен один контейнер `maxbot-app-1`, его порт `8000` доступен на хосте только через `127.0.0.1:8001`. Системный Nginx в `/etc/nginx/sites-available/maxbot.conf` принимает HTTPS для `85-159-231-99.sslip.io`, использует сертификат Let's Encrypt и проксирует запросы на `127.0.0.1:8001`. Порты 80/443 уже заняты Nginx; на том же сервере работают другие проекты. База приложения хранится в Docker volume `maxbot_buddy_data`; каталог `/opt/maxbot/data` сам по себе не является рабочей базой контейнера. Серверный `.env` содержит ключи MAX и RouterAI, отдельный админ-пароль и доверенный CA bundle; значения секретов здесь намеренно отсутствуют.

При аудите бот был запущен в режиме `polling`, хотя в MAX уже существовала webhook-подписка. 29 сентября режим серверного `.env` переключён на `webhook`, контейнер пересоздан, подписка обновлена. После этого публичный `/health` ответил HTTP 200 с корректным TLS, а контейнер получил статус `healthy`. Серверная копия исходников не является Git checkout; перед любым будущим развёртыванием нужно сравнивать её с зафиксированным commit и сохранять рабочий `.env` и Docker volume. На VPS также есть файлы резервных копий и другие сайты; они не входят в этот репозиторий и не должны удаляться при развёртывании.

Для повторного запуска существующего VPS используйте в `/opt/maxbot` команду `docker compose up -d --build` с серверным `.env` (`BOT_MODE=webhook`, `DEMO_MODE=false`, `PORT=8001`). Nginx и TLS уже настроены отдельно от Compose. Проверка: `docker compose ps`, `curl -fsS https://85-159-231-99.sslip.io/health`, затем открыть бота в MAX. Остановка только приложения: `docker compose down`; не используйте `down -v`, иначе удалится рабочая база. После изменения webhook-секрета необходимо повторно выполнить `docker compose exec app python -m app.cli webhook`.

## Сертификат MAX

Текущая [документация MAX](https://dev.max.ru/docs-api) указывает `platform-api2.max.ru` и доверие сертификату Минцифры. Проверку HTTPS приложение не отключает.

Если система не доверяет цепочке MAX, получите актуальный корневой/промежуточный сертификат из официального источника Минцифры/Госуслуг (уточните у организаторов хакатона). Поместите PEM-сертификаты в `certs/max-ca.pem`; несколько PEM-блоков можно объединить в одном файле. Папка `certs/` уже подключается внутрь контейнера как `/certs` только для чтения. В `.env` укажите:

```dotenv
MAX_CA_BUNDLE=/certs/max-ca.pem
```

Это добавляет доверие для клиента MAX к системным сертификатам. Не указывайте путь с вашего Mac внутри контейнера. Сертификат для исходящих запросов MAX и публичный HTTPS вашего сайта — разные настройки.

## Разработка бота без webhook

Можно использовать `BOT_MODE=polling`, `DEMO_MODE=false`. Для mini-app по-прежнему нужен публичный HTTPS URL и его настройка в MAX. Не включайте polling, пока у бота активна webhook-подписка: MAX не допускает одновременную работу. Управление существующими подписками намеренно не выполняется автоматически. Для сервера используйте webhook.

Бот отвечает в личном диалоге приветствием и ссылкой на мини-приложение. Выбор темы, теория и ответы проходят **в мини-приложении**, не в переписке. Входящие события сохраняются в SQLite перед подтверждением webhook, повторные доставки одного события не создают повторную задачу. Ошибки отправки повторяются до восьми раз с задержкой. После исчерпания попыток событие сохраняется со статусом failed; подробности — в логах. При остановке ровно между успешной отправкой MAX и фиксацией результата возможен повтор приветствия — внешнее API не даёт транзакции с нашей базой.

## Что хранится и как работает настроение

- Уникальный MAX ID, отображаемое имя, один случайно выбранный класс от 1 до 7. Ранее случайно присвоенные 8-й и 9-й классы автоматически переводятся в 7-й при обновлении версии; вручную выбрать свой реальный класс в MVP пока нельзя.
- Расписание до конца учебного года: четыре урока в учебный день и домашние задания. Для 1–4, 5–6 и 7 класса используются разные синтетические наборы предметов; уже созданные записи расписания сохраняются. Проверочные в начальном наборе не заданы; администратор может добавить их через панель. Это **синтетические данные**, не интеграция с настоящим дневником.
- Уроки, текущий шаг, последние разборы ответов. Сами тексты ответов в базе не сохраняются; отправляются RouterAI только для проверки.
- Сессии входа (24 часа), очередь событий MAX. Первичная подпись MAX принимается не старше часа.

Настроение Лучика привязано к правильным ответам за текущий календарный день по часовому поясу `Asia/Yekaterinburg`: цель — решить два разных вопроса, шкала показывает до пяти решений. Повторные попытки и неверные ответы зачёт не увеличивают. Счёт сохраняется в SQLite между сессиями. На шаге ученик остаётся, пока не ответит верно; AI объясняет ошибку и даёт новую наводящую подсказку, постепенно помогая самостоятельно найти решение. Сырые тексты ответов в базе не сохраняются. Старые завершённые уроки сохраняются как есть: прежняя версия не записывала ответы, поэтому подтвердить правильность пройденных шагов невозможно.

Персонаж использует локальные состояния `app/static/mascot-*.png`. Во время генерации урока и проверки ответа показывается локальный ролик `app/static/mascot-thinking.mp4`; приложение воспроизводит его без звука, по кругу и inline. Если видео не запустилось или включено уменьшение движения, остаётся статичная иллюстрация.

В PDF перечислены поля `DATA-API.yaml`, но нет формальной схемы имён ключей; перед сдачей следует сверить формат файла с организаторами. Для рабочего API нужен свежий `WebAppData` собственного тестового аккаунта MAX, который обменивается на сеансовый токен через `/api/auth/max`. Реальные тестовые логины, пароли и токены следует передать только установленным каналом технической проверки, не через Git.

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/auth/max` | Проверка `init_data`, выдача токена сессии |
| POST | `/api/register` | Создание аккаунта и дневника (повтор безопасен) |
| GET | `/api/me` | Профиль, настроение и последний урок |
| GET | `/api/diary` | Личный тестовый дневник |
| POST | `/api/lesson-jobs` | Запуск фоновой подготовки пяти блоков по `subject` и `topic` |
| GET | `/api/lesson-jobs/{id}` | Статус подготовки и готовый урок |
| POST | `/api/lessons` | Прямая генерация пяти блоков для старых клиентов |
| GET | `/api/lessons/{id}` | Текущий блок и прогресс |
| POST | `/api/lessons/{id}/answer` | `block_index`, `answer`: проверка ответа |
| POST | `/api/lessons/{id}/cancel` | Отмена активного занятия |
| POST | `/api/lessons/{id}/simplify` | `block_index`: более простая теория и пример текущего шага |
| POST | `/api/lessons/{id}/next` | `block_index`: переход после разбора |
| POST | `/webhook/max` | Приём событий с секретом MAX |

После входа защищённые запросы используют `Authorization: Bearer <токен сессии>`. Ключи MAX и RouterAI клиенту не передаются. Эталон ответа скрыт до разбора. Бот и backend работают в одном процессе; запускайте ровно один worker и один экземпляр приложения, поскольку блокировки учебных шагов локальные. Максимум 20 учебных AI-запросов в минуту на аккаунт и два одновременных обращения к AI на сервис.

## Админ-панель расписаний

Задайте в серверном `.env` отдельный `ADMIN_PASSWORD` длиной от 16 символов, затем пересоздайте контейнер приложения. Панель откроется по `/admin` через HTTPS. Пароль не используется для входа учеников: у администратора отдельная сессия в защищённой cookie на 8 часов. Если пароль не настроен, панель недоступна.

В панели можно найти всех зарегистрированных учеников по имени или ID, посмотреть их локальное расписание, добавить занятие, изменить его или удалить. Изменения сохраняются в той же SQLite-базе и доступны через `/api/diary` выбранного ученика. Исходные записи расписания — **синтетические**; интеграции с настоящим школьным дневником сейчас нет. Админ API находится под `/api/admin/`, принимает изменения только после входа и с заголовком `X-Admin-Action: 1`.

## База и обслуживание

SQLite хранится в Docker volume `buddy_data` (Compose добавит имя проекта к названию). `docker compose down` сохраняет базу. **`docker compose down -v` удаляет её.** Не меняйте имя Compose-проекта, если хотите продолжить с прежней базой.

```sh
docker compose logs -f --tail=100 app
docker compose ps
docker compose down
```

На текущем VPS с системным Nginx используйте обычные команды `docker compose`. Пару `-f compose.yaml -f compose.production.yaml` добавляйте только на новом сервере, где запускается Caddy из проекта.

## Тесты без ключей и платных вызовов

Python 3.10+ локально, Python 3.12 в Docker:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Проверяются подлинность входа, повторная регистрация, изоляция аккаунтов, пять шагов, сохранение при сбое AI, запрет пропуска, формат RouterAI, отключение демосессий в реальном режиме и повторная доставка webhook. Известные предупреждения об устаревших интерфейсах тестового HTTP-клиента не влияют на выполнение приложения.

## Ограничения и условия пилота

Дневник полностью синтетический и помечен `mock: true` в API. Класс выбирается случайно; расписание заполняется локально на учебный год. Учебные ответы зависят от внешнего RouterAI, поэтому при его сбое создание урока или проверка ответа временно недоступны. Настоящие данные несовершеннолетних для демонстрации не требуются. Работа основного сценария внутри мобильного и веб-клиента MAX должна быть проверена человеком с доступом к обоим клиентам; HTTP-проверка сервера этого не доказывает.

Первый продуктовый пилот разумно ограничить одной группой учеников 1–7 класса и тестовыми темами. Он ещё не проводился: опрос 49 учеников 7–9 классов был исследованием проблемы, а не испытанием продукта. Для переноса в другую школу сохраняются бот, учебный сценарий и модель прогресса, а расписание, темы, доступ к источникам и правила обработки данных требуют адаптации. Презентация PDF с техническим первым слайдом обязательна для сдачи по условиям трека и готовится отдельно от исходного кода.

## Пошаговая проверка

1. Для локальной проверки скопируйте `.env.example` в `.env`, выполните `docker compose up -d --build` и откройте <http://localhost:8000/>. Ожидается кнопка входа в деморежим; MAX и RouterAI для него не нужны.
2. Создайте демоаккаунт, выберите математику и тему «Обыкновенные дроби». Ожидается урок из пяти блоков. Неверный ответ оставляет ученика на текущем шаге, правильный позволяет перейти дальше; после двух верных ответов меняется настроение Лучика. После обновления страницы урок продолжается.
3. На сервере откройте [бота](https://max.ru/t696_hakaton_max_bot) в MAX, отправьте `/start`, откройте мини-приложение, создайте учебный аккаунт и пройдите урок. Ожидаются профиль, синтетическое расписание и сохранение прогресса. Этот шаг требует реального клиента MAX и работающего RouterAI; один HTTP `health` его не заменяет.
4. Для API используйте порядок из `DATA-API.yaml`: свежий `WebAppData` → `/api/auth/max` → `/api/register` → `/api/me` и `/api/diary` → `/api/lesson-jobs` → опрос статуса по `id`. Тестовая тема указана в `test-data/api-scenario.json`; ответ модели и идентификаторы динамические.
5. Остановите локальный запуск командой `docker compose down`; повторно запустите `docker compose up -d`. Профиль и прогресс должны сохраниться в Docker volume. `down -v` удаляет локальные данные и не подходит для проверки сохранения.
